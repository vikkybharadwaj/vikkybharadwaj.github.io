Session lifecycle

When each primitive activates over a single working session. Anchors are loaded the whole time; hooks fire deterministically at lifecycle events; policies load only when their trigger fires; skills run on demand; memory is read at the start and written at the end. The same shape every session — which is what makes the reconstruction tax go to zero.

Hooks vs. Policies vs. Skills

The three primitives people most commonly blur together — different in who runs them, when, and what they’re best for. Keeping them distinct is what makes the system legible, and what makes designing the human↔AI division of labour an actual, demonstrable skill.

Dimension Hooks Policies Skills
Tripwire Checklist Playbook

4

The anti-drift loop — the part I’m proudest of

The rule that makes the system durable: any new primitive must update every registry that names it — including this diagram — or the change fails its own audit. Adding a skill, for example, forces all four steps below. Skip one and the loop blocks the merge.

STEP 01

The primitive lands

A new skill (or hook, policy, folder) is added in its own place in the workspace.

STEP 02

A policy fires

The register-everywhere policy triggers: “this exists now — register it in every place that lists it.”

STEP 03

Every registry updates

The index, the capabilities map, and the self-portrait diagram all update to include it. Map = territory again.

STEP 04 · THE GATE

An audit checks

A structural-drift check at session start, plus a review gate before merge, compare the diagram to reality. Mismatch → blocked.

The payoff: six months on, the map is still the territory. A newcomer can trust the system’s description of itself, because the system can’t let that description go stale. That’s the difference between a project that decays the moment its author leaves and one that explains itself to the next person — and it’s why this very page can be trusted as a current map, not a stale screenshot.

5

How the system maintains itself

The cadences and automations that keep the workspace current and its description honest — the “self-improvement layer” that turns a docs folder into an operating system.

Per session start

Frame & refresh

Hooks pull the latest source, run the structural drift-check, and re-load memory — so the agent starts informed against current anchors, every time.

On situational trigger

Judgement, applied

The matching policy loads only when its situation arises — consistent judgement exactly when it’s needed, without bloating context the rest of the time.

Every PR (always)

Register or be blocked

A new primitive must update every registry that names it, including this diagram. A review-gate blocks the merge on mismatch — drift is caught before merge, not in review.

On discovery

Learnings loop

A non-obvious insight from real work is appended to the learnings-log — and re-loaded next session, so the same lesson isn’t re-learned twice.

Recurring upkeep

Maintenance cadence

A scheduled pass prunes the learnings log, retires orphaned folders, and refreshes stale specs — the unglamorous rigor that keeps a system honest over time.

Continuously

The system audits itself

Governance closes the loop: ownership decides who merges what, and the anti-drift audit (§4) ensures the map can never quietly fall out of sync with the territory.
