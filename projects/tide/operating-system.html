How the system maintains itself

The cadences and automations that keep the workspace current and the docs honest — Tide's "self-improvement layer."

Per session start

Role detection

scripts/session-role.sh probes ports 3333 / 8081 / 5432 / 6379 and prints whether this session is the dev-stack OWNER or a CONSUMER, so parallel sessions don't collide on the shared DB or port.

Every PR (always)

Code + docs move together

Changing schema, API flows, security model, or the AI pipeline requires updating the matching .md + .html maps in the same PR. data-flow-map.html is the product spec — code and flow must never drift.

On discovery

LEARNINGS loop

When a bug, crash, or non-obvious stack fact surfaces, it's appended to docs/LEARNINGS.md automatically — reviewed before writing mobile code to avoid repeating known pitfalls.

Every push / PR to main

CI: lint, typecheck, test

.github/workflows/ci.yaml runs lint + typecheck + tests against an ephemeral Postgres. Reused by deploy.yaml as a pre-deploy gate.

AI changes + nightly

AI eval suite

.github/workflows/evals.yml runs on changes under apps/backend/app/services/ai/** or evals/**, plus a nightly cron — scored against fixtures + judges.

On merge to main

Docs auto-publish

GitHub Pages publishes the docs/ folder, so this page and every visual map go live at vikkybharadwaj.github.io/tide without a build step.
