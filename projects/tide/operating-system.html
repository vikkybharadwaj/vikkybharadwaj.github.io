Session lifecycle

When each Claude Code primitive activates over a session. The harness fires hooks deterministically; Claude reads anchors (CLAUDE.md) and applies its conventions/guardrails as situations arise; slash-command skills run only when invoked. MCP servers are available the whole session once configured; subagents get isolated context for delegated work. Routines sit outside the session entirely — scheduled cloud agents that fire on a cron clock with your laptop closed.

Hooks vs. Conventions vs. Skills vs. Agents vs. Routines

The five layers people most commonly confuse — different in who runs them, when, what they're best for, and crucially whether they get their own context and a restricted toolset. In Tide, the "policy" layer lives as conventions inside CLAUDE.md rather than a dedicated policies/ folder. Agents are isolated helper Claudes under .claude/agents/; Routines are the newest layer and the only one that runs with no session at all — a scheduled agent firing on a cron clock in the cloud, laptop closed.

How the system maintains itself

The cadences and automations that keep the workspace current and the docs honest — Tide's "self-improvement layer." The throughline of the latest iteration: migrate the highest-risk rules out of the §3 "Conventions judge" column (which depends on Claude remembering) and into the "Hooks fire" column — deterministic tripwires that cannot be silently skipped. The cards below are tagged tripwire (harness-enforced), convention (Claude judgment), CI (GitHub Actions), or routine (scheduled cloud agent).

Per session start · SessionStart hook

Role detection tripwire

scripts/session-role.sh probes ports 3333 / 8081 / 5432 / 6379 and prints whether this session is the dev-stack OWNER or a CONSUMER, so parallel sessions don't collide on the shared DB or port.

Per session start · SessionStart hook

Context injection tripwire

scripts/session-context.sh injects the latest docs/LEARNINGS.md entries (newest N=8) + the MEMORY.md index into every session's context at start. A SessionStart hook's stdout is added to the model's context, so a fresh session boots already aware of recent lessons + project memory — the just-in-time / progressive-disclosure pattern (surface a digest, not the whole file).

After compaction · SessionStart(compact) hook

Post-compaction re-grounding tripwire

scripts/precompact-context.sh fires on SessionStart with source=compact — the only hook that can inject context into the freshly compacted window (PreCompact can't). It re-asserts the compaction-specific delta: the in-flight branch + uncommitted work, any spec-bearing edits that still owe a doc sync in this PR, the ./NOTES.md working-memory scratchpad, and a "recall may be degraded — re-verify paths/flags" checklist. Directly implements Anthropic's guidance to preserve architectural decisions + unresolved work across compaction.

Per edit · PostToolUse(Edit/Write) hook

Doc-sync tripwire tripwire

scripts/doc-sync-guard.sh fires the moment an edit lands on a spec-bearing path (a migration, a route/controller, services/ai/**, a mobile screen) and injects an explicit reminder of exactly which .md + .html maps now owe an update in the same PR. The old "code + docs move together" mandate was convention-only — now the harness raises it on every relevant edit. data-flow-map.html is the product spec; code and flow must never drift.

Every /ship that touches docs/*.html · ship step 6.6

Portfolio-mirror sync new

The portfolio site (vikkybharadwaj.github.io/projects/tide/) republishes most of docs/*.html — and for two weeks nothing synced it, so it kept showing features the app had removed. scripts/sync-portfolio.sh makes the mirror a build artifact: manifest-driven from .claude/doc-map.json (portfolio_mirror), it copies every published page, re-applies the mirror's nav transform, deletes orphans, and warns when the hand-owned portfolio landing's stat numbers fall behind. /ship step 6.6 runs it in the same ship cycle as any docs change; /doc-drift runs --check as its 8th sweep area. Mirror pages are never hand-edited again.

Per edit + every /ship · PostToolUse hook + ship step

Changelog freshness tripwire tripwire

This page's Changelog (top-right button) bills itself as sourced from the commit history — but it was a hand-maintained array, so it silently froze at #11 while five more PRs shipped without a row. Now scripts/sync-changelog.py regenerates it from the file's real git log (date, ET time, author, PR#), only ever appending so hand-curated highlight prose survives. /ship records each PR's own row in the same PR (no one-ship lag), and scripts/changelog-guard.sh is the PostToolUse backstop that re-flags the list the instant it falls behind committed history. The textbook convention→tripwire migration, turned on the page that describes it.

On any bug fix · model-invoked skill

LEARNINGS loop tripwire

The update-learnings skill (.claude/skills/) carries a description that lets Claude self-invoke it whenever a bug is fixed, a crash resolved, or a non-obvious stack fact discovered — appending a dated, root-caused entry to docs/LEARNINGS.md in the same PR. Upgrades the old "remember to append" convention into a model-invoked routine, reviewed before mobile work to avoid repeating known pitfalls.

Per command · PreToolUse(Bash) hook

Budget + security deny-wall tripwire

scripts/budget-guard.sh hard-denies any Bash command that would create a budget-busting AWS resource — eks, nat-gateway, elbv2/ALB, elasticache, secretsmanager — with a reason pointing to STACK_DECISIONS.md. The $46/mo budget Gotcha was convention-only; now a careless or prompt-injected agent physically cannot run the forbidden command.

Per command · PreToolUse(Bash) hook

CONSUMER collision guard tripwire

scripts/consumer-guard.sh re-probes :3333 on every Bash call: if a stack is already up (this session is a CONSUMER), it denies duplicate service starts — node ace serve / queue:listen / npx expo start / docker compose up — and asks for confirmation before a shared-DB migration. session-role.sh only warned; this enforces it, killing the port-conflict / zombie-process / shared-DB-corruption class for parallel sessions.

Per edit · PostToolUse(Edit/Write) hook

Security invariant tripwires tripwire

scripts/security-guard.sh inspects the file just edited and flags likely breaches of the fintech non-negotiables: an encrypted column missing serializeAs: null, PII in a console.* call without redactForLogging(), a direct Plaid SDK call outside PlaidAdapter, or a DB write from the read-only services/ai/** layer. The ORM-level encryption + Bouncer discipline was convention-only; now a violation surfaces the moment it's typed.

Pre-PR / on demand · subagent

Spec-drift auditor tripwire

The spec-auditor agent (.claude/agents/, read-only) checks that data-flow-map.html still matches the code — parsing each flow's spec block (windows, thresholds, formulas, tool shapes) and diffing it against the implementation, then adversarially confirming before reporting drift. Makes DATA FLOW = SPEC a checkable invariant and materializes the long-referenced "Riu" reviewer persona as a real project agent.

Nightly · 07:00 UTC · cloud routine

Nightly doc-drift sweep routine

A claude.ai routine (Opus 4.8) fires nightly at 07:00 UTC (3am ET) on a fresh cloud checkout — no machine of yours involved. It diffs every tracked doc against the code — data-flow-map.html, DATABASE.md, ARCHITECTURE.md, the security / ai-pipeline / cost maps, and the landing-page counts — and, when it finds drift, opens ONE review-only docs: PR citing each mismatch as doc:line → code:line; finds nothing, opens nothing. The cloud cousin of the spec-auditor agent — same DATA FLOW = SPEC discipline, but unattended, on a clock, and across the whole doc set. Managed at claude.ai/code/routines.

Every push / PR to main · GitHub Actions

CI: lint, typecheck, test CI

.github/workflows/ci.yaml runs lint + typecheck + tests against an ephemeral Postgres. Reused by deploy.yaml as a pre-deploy gate.

AI changes + nightly · GitHub Actions

AI eval suite CI

.github/workflows/evals.yml runs on changes under apps/backend/app/services/ai/** or evals/**, plus a nightly cron — scored against fixtures + judges.

On merge to main

Docs auto-publish

GitHub Pages publishes the docs/ folder, so this page and every visual map go live at vikkybharadwaj.github.io/tide without a build step.
