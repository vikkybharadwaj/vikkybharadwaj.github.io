How Evals Work

Every eval run follows this pipeline. A fixture defines the scenario, the runner sends it through the AI, and three independent judges score the output.

mock tool data

→

→

Per-dimension
verdict

Key insight: The runner replays mock tool responses instead of hitting real APIs. This makes evals deterministic, fast, and free of external dependencies. The same fixture always produces the same tool data, so any variation in the final response comes from the model itself.

Three Judge Layers

Each response is evaluated by up to three independent judges, layered from cheapest/fastest to most thorough.

Layer What It Checks How Speed Cost
Code Checks Mechanics: tools called, numbers mentioned, forbidden content Regex + string matching Instant Free
Rubric Judge Quality across 7 dimensions LLM (Haiku) scores against rubric ~1s ~$0.003
Ground Truth Judge Content similarity to PM's golden answer LLM (Haiku) compares responses ~1s ~$0.003
Why three layers? Code checks catch mechanical failures instantly and for free — no LLM needed. The rubric judge evaluates subjective quality (via Claude Haiku). The ground truth judge compares against a PM-authored ideal answer. Both PR and nightly suites run all three layers across all 7 dimensions. Gating: pass/fail is decided by code checks + the rubric judge; the ground truth judge produces a 1–5 similarity score that is tracked on the dashboard as a quality signal, not a pass/fail gate.

Ground Truth Guide

How the PM writes golden answers and how the eval system compares AI responses against them. The benchmark that keeps Tide Coach aligned with the product vision.

Section 1: How Ground Truth Is Written

Ground truth is the foundation of eval quality. Without it, we are grading AI output against vague vibes instead of a concrete standard.

What Is Ground Truth?

A "golden answer" written by the PM (Vik) for each eval scenario. It represents what the ideal Tide Coach response should look like -- the benchmark every AI response is measured against.

  • Each of the 50 eval fixtures contains a ground_truth_response field
  • It is the single source of truth for "what good looks like" in that scenario
  • It captures product voice, specificity, empathy level, and data accuracy in one concrete example

Who Writes It?

The PM writes every ground truth response -- not the AI. The PM understands the product voice, the user empathy level, and what "good" looks like for a financial coach texting a friend.

  • Claude Code drafts initial versions based on the fixture data and personality guidelines
  • The PM reviews and edits every draft to match their vision of the product voice
  • The AI is the student being graded, not the teacher writing the answer key

The Writing Process

Each ground truth response follows a deliberate creation flow:

1
Start with a fixture (user question + mock financial data)
→
2
Read the system prompt personality guidelines
→
3
Write the response as if YOU were the coach texting a friend
4
Follow format rules: plain text, $X,XXX.XX currency, 2-3 paragraphs, no markdown
→
5
Include specific numbers from the mock data -- no rounding, no inventing
→
6
Match tone rules: warm, direct, specific, never generic

Ground Truth Principles

SPECIFIC, NOT GENERIC
"$340 on groceries" beats vague summaries
Not: "you're doing well with spending"
ACTIONABLE, NOT VAGUE
"skip 2 DoorDash orders this week" beats platitudes
Not: "try to save more"
EMPATHETIC, NOT ROBOTIC
"money stress is real -- let's look at the numbers"
Not: "I understand your concern. Here is your data."
HONEST, NOT SUGARCOATING
"your balance dips Thursday but recovers Friday"
Not: "everything looks fine"
BRIEF, NOT PADDED
60-120 words, no filler -- every sentence earns its place
Not: long essays with boilerplate intros and outros

Section 2: How Ground Truth Is Compared

The third eval judge layer. After code checks verify mechanics and the rubric judge checks rules, the ground truth judge checks whether the AI said what the PM would say.

The 3 Eval Layers

1

Code Checks (Deterministic)

Did it call the right tools? Did it mention the right numbers? Did it avoid forbidden patterns? These are pass/fail regex and tool-call checks with zero ambiguity.

2

Rubric Judge (LLM)

Does it follow the rules? Right tone? Right format? An LLM judge evaluates the response against dimension-specific criteria (projection accuracy, safety, tone, coaching actionability).

3

Ground Truth Judge (LLM)

Does it say what the PM would say? Compares the AI's actual response against the PM's golden answer for substance alignment -- same key points, same data, same conclusion.

What Each Layer Catches

Problem Type Code Checks Rubric Judge Ground Truth Judge
AI forgot to call a tool Catches it Might miss Might miss
AI used wrong dollar amount Catches it Might miss Catches it
AI used markdown formatting Might miss Catches it Does not check
AI tone was robotic Cannot check Catches it Catches it
AI missed the PM's key insight Cannot check Might miss Catches it
AI gave correct data but wrong conclusion Cannot check Might miss Catches it

How the Comparison Works

INPUT

User question + AI's actual response + PM's ground truth response

→
JUDGE MODEL

Claude Haiku 4.5 (cheap, fast -- designed for high-volume judging without budget strain)

→
OUTPUT

Similarity score (1-5) + reasoning explaining the comparison

Key Detail: Substance, Not Wording

Haiku compares substance, not exact wording. The AI does not need to match the ground truth word-for-word. It needs to hit the same key points, reference the same data, and reach the same conclusion. Different sentence structure, paragraph breaks, and phrasing are all fine.

The Scoring Rubric

5
Same key points, same data, same conclusion. Wording differs but content is equivalent. The PM would read this and say "yes, that's what I meant."
4
Covers most key points, may miss one minor insight. Still a strong response the PM would approve. Perhaps missed a secondary data point or nuance.
3
Gets the main point but misses important secondary insights. The direction is right but the depth or specificity falls short of what the PM envisioned.
2
Partially addresses the question but misses the core insight. The PM would say "it answered a different question" or "it buried the lead."
1
Fundamentally different -- wrong data, wrong conclusion, or completely missed the point. Something is broken in the prompt or tool pipeline.

What Scores Mean for the Product

Target: 4.0+ average across all fixtures. This means the AI consistently says what the PM would say, with minor variations in phrasing.
Score of 3 = "acceptable but needs prompt tuning." The AI gets the gist but is missing specificity or nuance the PM expects.
Score of 2 = "the prompt is drifting from the PM's vision." The AI is producing polished-sounding responses that miss the point.
Score of 1 = "something is broken." Wrong data, wrong conclusion, or the AI is ignoring tool responses entirely.

Why Substance Over Style

The judge does not penalize different wording, paragraph breaks, or sentence structure. What matters is whether the AI communicated the same information and reached the same conclusion as the PM.

AI RESPONSE

"Your rent is $1,450 due April 1. That's your biggest bill this month."

SCORE: 5
GROUND TRUTH

"Your rent of $1,450.00 is due April 1 -- that's coming up fast. Make sure your checking covers it."

REFERENCE

Both say the same thing: rent is $1,450, due April 1, it is the priority bill. The wording is different. The content is equivalent. That is a 5.

Rubric PASS Rubric FAIL
Ground Truth HIGH (4-5) Great -- ship it.
