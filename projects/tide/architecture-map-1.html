Cash Flow App

AI-powered personal cash flow management built on open banking infrastructure (Plaid). Predictive intelligence that helps everyday consumers understand their liquidity — what's coming in, what's going out, and whether they'll have enough.

🎯 Product Objectives
Predict, don't just report. Show consumers their future cash position — not just historical spending. 30-day daily balance projections with confidence scoring.

Coach, don't lecture. AI financial coaching that gives personalized, actionable recommendations — not generic budgeting tips. Remembers past advice and tracks follow-through.

Alert before it's too late. Proactive notifications when a cash crunch is approaching, with enough lead time to take action.

Bridge visibility and action. the strategic moat is being the only product that can both predict cash flow problems AND automatically move money to fix them via real-time rails (Phase 2+).
💎 Competitive Moat
Prediction + Execution. No competitor currently has both. Cleo ($250M ARR) can predict but can't move money on real-time rails. Monarch/Copilot show beautiful dashboards but have zero payment capabilities.

Competitive landscape splits into two categories:
Cash Access — Brigit, Cleo, EarnIn (advances, limited visibility)
Cash Visibility — Monarch, Copilot, YNAB, Rocket Money (dashboards, no execution)

Tide bridges both — powered by open banking data + real-time payment rails (RTP/FedNow via Cross River Bank).

Processing Pipelines

Four core pipelines drive the system. Each is visualized as a sequential flow showing the components involved, the data passed between them, and timing characteristics.

⚙️ Pipeline 1 — Transaction Sync

Daily at 2:00 AM CST + real-time via Plaid webhooks. Syncs bank transactions, enriches categories, detects income/bills, and generates 30-day balance projections.

🤖 Pipeline 2 — AI Chat

Multi-agent pattern: Intent Classifier (Haiku, <500ms) routes to Tide Coach (Sonnet) which selects from 9 tools. Responses stream via SSE. Chat messages persisted asynchronously.

🔐 Pipeline 3 — Authentication Flow

Passwordless SMS OTP via AWS Cognito. JWTs validated on every API request via JWKS. 18 Bouncer authorization policies enforce resource ownership. Tokens stored in Expo SecureStore (Keychain/Keystore).

🔔 Pipeline 4 — Notification Engine

Backend syncs user attributes via Lucid model hooks (@afterCreate, @afterSave). Frontend tracks 19 custom events across 4 categories. Alerts delivered via FCM push to iOS/Android. Phase 2 adds WhatsApp + Telegram channels.

🧠
AI / ML Architecture Claude Haiku 4.5 + Sonnet 4.6 · AWS Bedrock · 3-tier memory ▶
Intent Classifier
Claude Haiku 4.5
Fast query routing in <500ms. Determines query type and routes to the appropriate Tide Coach tool path. Lightweight model optimized for classification.
Tide Coach Agent
Claude Sonnet 4.6
User-facing AI financial coach with 9 tools. Selects tools based on intent, gathers data via DB queries (30-200ms) and API calls (200-500ms), streams personalized coaching responses.
Three-Tier Agent Memory Model
Tier 1 — Session
Current chat thread. Built into conversation. Resets between sessions.
Tier 2 — Financial Data
Accounts, transactions, predictions. Agent pulls on-demand via tools 1-8. Not pre-loaded into prompts.
Tier 3 — Coaching History
Past recommendations + user responses + outcomes. Enables continuity across sessions via tool 9.

2. Transport

JWT validation (aws-jwt-verify), 18 Bouncer policies, resource ownership checks, audit logging

AES-256 field encryption (PII), HMAC-SHA256 hashing (searchable indexes), TLS in transit

Row-level user_id filtering, read-only AI connections, connection pooling (max 20/pod)

CloudWatch structured JSON logs, 40+ PII fields redacted, X-Ray distributed tracing

🏗️ k3s Cluster Topology
Single EC2 t3.small instance runs a lightweight k3s Kubernetes distribution. All services run as pods within this cluster, sharing the instance's 2 vCPU and 2 GB RAM. This replaces a full EKS cluster ($73/month control plane alone) with a single-node setup that's sufficient for MVP-scale traffic.

🏛️ Design Patterns (Mirroring a Production-Scale Architecture)

Strategy pattern — Runtime switching: AI chat (LocalAgentRuntimeStrategy vs AuthenticatedAgentRuntimeStrategy), notifications (FCMService vs mock). Factory pattern — Instance creation: ChatServiceFactory, NotificationServiceFactory. Singleton pattern — Shared instances: notification client per service lifecycle. Template method pattern — Base listener classes for notification handlers.
