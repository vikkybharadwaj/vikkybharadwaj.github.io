About

Product and engineering, together.

I'm a product manager who works hands-on, and I keep one thing at the center: the customer and the outcome we're trying to move for them. On my current project, Tide, I've owned the product direction and specs as well as much of the implementation — the React Native app, AdonisJS services, the PostgreSQL data model, AWS infrastructure, and the Claude-based AI pipeline — so the path from a customer problem to a shipped, measured outcome stays short.

I'm especially interested in making AI features measurable — using evals (dimensions, fixtures, ground-truth, judge scoring) so quality is something you can track and improve rather than guess at. I also try to keep documentation as a living spec next to the code, so what's written stays in step with what's shipped.

What I do

Customer in, outcomes out.

I run product as a loop, not a checklist: start from the customer, ship the smallest bet that moves a real outcome, measure it, and feed what I learn straight back into the roadmap. The AI craft below — pipelines, evals, the data flywheel — exists to serve that loop, not the other way around.

The AI PM operating loop. Explicit signal (what users say) and implicit signal (what users do) feed every turn — and each turn compounds: more usage → more signal → a better model → more usage. That return arc is the data flywheel.
