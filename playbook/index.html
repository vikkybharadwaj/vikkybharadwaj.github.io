First, the mental model

You are the director. Claude is the builder.

Hold this one idea firmly and everything else gets easy: you manage Claude the way you've managed people and vendors. You give a crisp brief, react to drafts, and say "warmer," "shorter," "lead with the number." Claude handles the typing, the syntax, and the debugging. Your edge — knowing what a great strategy and a real financial result actually look like — is the part AI can't do. There are only four things in this entire world:

GitHub

A website that stores your files and remembers every version, forever.
Like: the shared drive + a filing cabinet that keeps every past draft of every document.
🌐

GitHub Pages

A free feature that turns your files into a live public website at a real URL.
Like: the printing press that publishes your cabinet to the world.
🤖

Claude Code

An AI that lives in your project, reads your files, and edits them when you ask.

CLAUDE.md

A plain-English brief you write once that Claude reads automatically, every time.
Like: the onboarding doc you give a new hire so you never repeat yourself.

"But a website is just files?" Yes — that's the whole trick. A website is a folder of plain-text files. The home page is one file called index.html. "HTML" is just the format browsers read, the way .docx is the format Word reads. You will never write it. You'll say "add a section about my Party City turnaround with three metric tiles," and Claude writes the HTML. You're the editor-in-chief; HTML is the typesetter's problem.

0
Level 0 · Crawl · ~45 min
Get something live today

The biggest motivation booster is seeing your own URL load in a browser. We'll do it with an almost-empty page first, then make it good later. Momentum before polish. The magic trick: name your repository exactly your-username.github.io and GitHub publishes it to the web for free, automatically.

Create your GitHub account

Go to github.com → Sign up. Choose your username carefully — it becomes part of your web address. If you pick vishwasbharadwaj, your site lives at vishwasbharadwaj.github.io. Use your real name; this is a public professional asset. Verify your email, pick the Free plan. Done — hosting is free forever.

Create the repository (your project folder)

Click New repository. Name it exactly your-username.github.io. Set it to Public, tick "Add a README," and click Create. A "repository" (repo) is just the folder that holds your website's files.

Add your home page

In the repo, click Add file → Create new file. Name it index.html and paste this starter (you'll never have to write HTML again after this — Claude takes over):

<!-- index.html — your home page --> <!doctype html> <html> <head><title>Vishwas Bharadwaj</title></head> <body style="font-family: system-ui; text-align:center; margin-top:20vh"> <h1>Vishwas Bharadwaj</h1> <p>Site coming soon.</p> </body> </html>

Scroll down, click Commit changes. ("Commit" = save a snapshot.)

Add the .nojekyll file

Add file → Create new file → name it .nojekyll (the leading dot matters) → leave it empty → Commit. This one tells GitHub "publish my files exactly as they are." Leave it there forever.

Turn on the website

Go to Settings → Pages. Under "Source," choose Deploy from branch, pick branch main and folder /(root), then Save. Wait about a minute.

Open your live site 🎉

Visit https://your-username.github.io. There it is — a real website, on the real internet, that you own. It's plain. That's perfect: from here you only ever improve it. Take a screenshot — that's your "before."

⚡ DOPAMINE CHECK

You just shipped a website without a developer, a designer, or a hosting bill. Text a friend the link. That feeling — "I made a thing that's live" — is the engine. Everything from here is just making this page better, by talking to an AI.

1
Level 1 · Crawl · ~1 hour
Talk to Claude & learn the loop

Now we hand the keys to Claude so you can edit by talking. You have two options — pick by comfort. Most non-technical people should start with the web version.

Get Claude (a paid plan)

At claude.ai, create an account and subscribe to Claude Pro (think "one nice dinner" a month). Claude Code needs a paid plan to run. If you build heavily every day, Max gives more headroom — but start with Pro.

Choose how you'll run Claude Code

  • Easiest — Claude Code on the web. Go to claude.com/code, connect your GitHub account, point it at your repo, and work from the browser (even your phone). No installing. Start here.
  • The classic desktop tool — the terminal. Worth graduating to. Don't fear the word "terminal": you'll type whole English sentences into it, not code. Install with one line (next step).

(Terminal route) Install & open your project

Open the Terminal app (Mac: ⌘+Space → "Terminal"; Windows: "Windows Terminal" from the Store). Paste these one at a time:

# install Claude Code (one time) npm install -g @anthropic-ai/claude-code # download your repo to your computer ("clone" = linked copy) cd ~/Documents git clone https://github.com/your-username/your-username.github.io.git cd your-username.github.io # start Claude inside your project claude

If it says npm not found, install Node.js from nodejs.org (the "LTS" button), reopen Terminal, try again. The first time you run claude, it opens a browser to log in. Now Claude can see and edit every file in this folder.

Your first conversation: ask before you act

Try exactly this — notice you're not asking it to change anything yet:

You're helping me, a non-technical eCommerce/DTC executive, build my portfolio. First, just describe in plain English what's currently in this project and what the home page looks like. Don't change anything yet.

You just had Claude explain your own site to you. "Explain this to me before we change it" is a move you'll use forever.

Make your first real edit (the loop, live)

Now run the loop. Keep changes small and reviewable:

Make one change: replace "Site coming soon" with a one-line value proposition for a senior eCommerce & DTC P&L leader, and make my name bigger and bolder. Show me your plan in 2 bullets first. After I approve, make only that change and tell me what to refresh to see it.

Approve the plan, let it edit, refresh your browser. Iterating 3–5 times on one line is normal — "warmer," "shorter," "more senior."

Publish it — and meet versioning

When you like it, publish. Either say "save and publish that for me" (Claude runs it), or run the three-command "save & ship" yourself:

git add -A # stage my changes git commit -m "Add value-prop headline" # save a labelled version git push # send it to GitHub → live in ~1 min
🧭 VERSIONING = YOUR INFINITE UNDO

Every commit is a saved snapshot kept forever. This is the single most reassuring fact in this whole playbook: you can never permanently break anything. If a change makes the site worse, just say "that made it worse — undo your last change and take us back to how it looked before." Claude reverts it. You are working with an infinite undo button. Build fearlessly.

💡 TWO HABITS THAT MAKE YOU GOOD FAST

1. Ask for the plan first: "Before changing anything, give me your plan in 3 bullets." Approve, then build. (In the terminal, Shift+Tab toggles "Plan mode" — Claude proposes, you approve, it executes.)   2. One change at a time. Not "redesign my site" — "make the headline bigger and change it to X." Small, reviewable steps. Go faster later.

2
Level 2 · Walk
Give Claude a brief — Memory & Context

This is the highest-leverage rung. Right now you re-explain "I'm non-technical, keep it senior, never invent numbers" on every request. We'll fix that with memory (a brief Claude reads automatically) and context (your real career material). After this, output sounds like you.

A · Memory — your CLAUDE.md

CLAUDE.md is a plain-text file in your project that Claude reads first, every session, automatically — no need to mention it. It's the standing brief, the onboarding doc, and the house style guide in one. Write it once; benefit on every prompt forever. The easiest way to make it is to ask Claude to, then paste this starter (edit the brackets):

# CLAUDE.md — Working brief for my portfolio ## Who I am I'm [Vishwas Bharadwaj], a senior eCommerce / DTC / marketplace executive with 15+ years owning P&L (up to ~$350M), GM, marketing, and team leadership. I am NON-TECHNICAL — I've never coded. Explain things in plain business English and do the technical work for me. ## How to work with me - Before any non-trivial change, give me a 3-bullet plan and wait for my go-ahead. - Make ONE change at a time; tell me exactly what to look at to check it. - After each change, offer to save & publish, and remind me it's live in ~1 min. - When you must show code, keep it minimal with a one-line plain-English caption. - If I ask for something that would break the site, say so and propose better. ## Voice & content rules (important) - Confident, senior, results-first voice. Lead with outcomes and numbers. - NEVER invent or inflate metrics. Use ONLY numbers I give you. If one is missing, leave a clear placeholder like [ADD METRIC] — never guess. - Prefer specifics ("grew DTC +38% to $X over 2 yrs") over adjectives. - Skimmable: short sections, strong headlines, metric tiles, scannable bullets. ## Technical guardrails - Keep the stack simple: hand-written HTML/CSS, no frameworks, no build step. - Self-contained in one repo; relative links; keep the .nojekyll file. - No analytics/trackers/third-party scripts without asking me first. - Don't delete files without confirming with me. ## My links (use these, don't guess) - LinkedIn: [paste URL] · Email: [you@email] · GitHub: [your URL]
⚠ THE RULE THAT PROTECTS YOUR CAREER

The line "never invent metrics" matters more than any other. AI can sound confident while being wrong — especially with numbers. You are the only authority on your own career. This rule makes Claude leave a [ADD METRIC] placeholder instead of guessing "$500M" when the truth was "$350M." Verify every number on the live page before you share it.

🧠 TWO LEVELS OF MEMORY

Project memory = the CLAUDE.md inside this repo (rules for this site). Personal memory = a file at ~/.claude/CLAUDE.md on your computer (rules for everything you build — e.g. "I'm non-technical; always explain plainly"). Quick add: in a session, start a line with # and Claude saves it to memory for you. Edit anytime with the /memory command. Living document: anything you correct twice, add as a line so it never happens a third time.

B · Context — give Claude your truth

Claude only knows what's in front of it. It does not know your career unless you hand it the material. Good output is mostly good context — gold in, gold out. Before asking it to write your "Experience" section, drop your real career documents into a folder:

your-project/ index.html CLAUDE.md content/ ← your raw material (you decide what's public) linkedin.txt ← paste your full LinkedIn profile text achievements.md ← real numbers: revenue, growth %, P&L size, teams roles/ party-city.md ← one file per role: the story + the metrics dormify.md newell.md

Now your prompt becomes: "Using content/roles/party-city.md, write a case-study section. Lead with the financial result. Use only the numbers in that file." Claude is working from your truth, not its imagination. Spending 20 minutes dumping your LinkedIn export and real numbers into content/ on day one is the best investment you'll make — everything downstream gets better.

⚠ PRIVACY

Your repo is public — anything in it (including content/) can be found if someone digs. Don't commit anything you wouldn't put on LinkedIn (confidential employer figures, private contact details). Unsure? Ask Claude "is this safe to make public?" before publishing.

Level 3 · Walk
Build the substance, safely

Here your expertise dwarfs any developer's. A great portfolio for a commercial leader isn't a résumé reprint — it's a highlight reel of outcomes, organized so a hiring CEO or recruiter "gets it" in 20 seconds and can go deeper. Build the home page around this proven structure (it mirrors how strong operator portfolios — and this very site — are built):

Hero

Name, a one-line positioning statement ("eCommerce & DTC P&L leader — I scale marketplace and direct businesses from $0→$300M+"), and 3 headline metrics. Your billboard.

The numbers strip

4–6 metric tiles quantifying your career at a glance: P&L owned, revenue grown, channels launched, teams led, years. CFOs love this; recruiters screenshot it.

Selected work — 3–4 case studies

Each a "front-door card" opening to a one-page deep dive. Use one repeatable template: Situation → Strategy → Action → Result → Leadership. Strong candidates from your background: the Party City marketplace turnaround, the Dormify DTC build, a Newell channel expansion, a GMV-tripling peak-season play.

How I operate

Your leadership & operating philosophy — people, team-building, how you run a P&L. The "would I want to work with this person" section. Pure you.

Capabilities · About · Contact

A scannable capability grid (DTC, Amazon/marketplaces, P&L, demand gen, pricing & margin, omnichannel, team leadership), a short human bio, and a clear "let's talk" with LinkedIn + email.

Using my files in content/ (especially linkedin.txt and achievements.md), rebuild index.html as a modern single-page portfolio with these sections in order: hero, metrics strip, selected work (3 front-door cards), how I operate, capabilities grid, about, contact. Follow the structure and voice rules in CLAUDE.md. Use ONLY the metrics in my files; mark anything missing [ADD METRIC]. Show me the plan first. Make it look senior and clean — generous whitespace, strong type, one accent color.

On design — you don't need design words. React like a buyer: "looks dated," "too busy," "I want it to feel like a premium consultancy," "show me three color directions." Claude translates taste into CSS. Seen a site you love? "Make mine feel more like that" and describe it.

Working safely — branches & pull requests

Ready to work like a pro (~week 2–3)? Two concepts give you a total safety net:

  • Branch = a private sandbox copy of your site. The live version keeps running off main; you experiment on a branch; you merge it in only when you love it. "Create a branch called redesign-hero so we can try a bold new homepage without touching my live site."
  • Pull Request (PR) = a "please review & merge this batch" proposal, with a tidy before/after summary. Even solo, it gives you a clean review screen and a record of why each change happened. "Open a draft pull request summarizing what we changed and why."
🧭 THE MENTAL MODEL

main is the published magazine. A branch is the rough draft on your desk. A PR is handing that draft to the editor (you) before it goes to print. You don't need branches on day one — use the simple save/publish loop until it's comfortable, then graduate.

4
Level 4 · Run · optional, when curious
Teach Claude your standards

Everything so far works without this rung — climb it only when you find yourself repeating the same instructions or wanting tighter guardrails. These are the tools that turn Claude into your operating system. Three ideas, easy → advanced.

A · Skills — package work you repeat

A Skill is a saved set of instructions Claude can run on command — a repeatable routine you describe once. Instead of re-typing your whole "write a case study" brief, you save it as a skill and just invoke it by name. Think saved playbooks / macros. Ask Claude to create one for you:

Create a Skill called "case-study" that takes a role file from content/roles/ and writes a one-page case study using my Situation→Strategy→Action→Result→Leadership template and the voice rules in CLAUDE.md. Save it in .claude/skills/ so I can run it anytime. Explain in plain English how I invoke it.

Now each new role is a one-liner: "use the case-study skill on content/roles/dormify.md." (A lighter cousin is a custom slash command — a shortcut for a prompt you reuse, saved in .claude/commands/. Same idea, smaller.)

B · Policies — permissions & guardrails

Permissions let you decide what Claude may do freely vs. what it must ask about first. You set these once in a settings file; Claude can write it for you. For a non-technical owner the sweet spot is: let it edit and preview freely, but always ask before deleting files or publishing to the live site.

Set up my Claude permissions so you can read, edit, and preview files freely, but you must ASK me before deleting any file or pushing to the live site. Put it in .claude/settings.json and explain each rule in one line.
💡 WHY THIS HELPS

Good guardrails make you faster, not slower: once Claude can act freely on the safe stuff, you stop approving every tiny step — while the risky moves still pause for your sign-off. It's delegation with a clear mandate, exactly like running a team.

C · Hooks — things that fire automatically

A hook is an action that runs by itself when something happens — no asking required. It's the difference between "Claude does it when I ask" and "it just happens." Useful, low-stakes examples for a portfolio:

  • On session start: show a 3-line checklist ("here's where we left off; here's your backlog").
  • After every edit: automatically check for broken links and flag them.
  • Before publishing: auto-scan for any leftover [ADD METRIC] placeholder so you never ship a gap.
Add a hook that, before any publish, scans my site for the text "[ADD METRIC]" and warns me if any remain so I never publish an unfinished number. Put it in my Claude settings and explain in plain English what it does and how to turn it off.
⚠ DON'T RUSH THIS RUNG

Skills, permissions, and hooks are power tools. They're genuinely valuable — and great proof of AI fluency — but you'll get the most from them after the core loop is second nature. If a section here feels abstract, that's a sign to keep living on Levels 1–3 a bit longer. Come back when you catch yourself thinking "I keep doing this same thing."

Level 5 · Run · the graduation
Automate — routines & loops

A loop is work that runs on a schedule, automatically, without you starting it. Instead of "I prompt → it acts once," it's "I set up a recurring job → it acts forever." This is the genuinely impressive part of the AI-builder skillset — and a real "I built an autonomous workflow" story to put on the portfolio.

A · The recurring prompt (easiest)

Ask Claude to repeat a task on a timer while you work — e.g. "every 10 minutes, re-check the site for broken links and tell me." Great for polishing sessions; zero setup.

B · The scheduled automation (the prize)

This is the pattern behind "live stats" on operator portfolios — numbers that refresh on their own with no one touching a computer. A GitHub Action is a free robot living in your repo that runs a task on a schedule (say, daily at 5pm) on GitHub's own machines, then publishes the result. You won't write it — you'll describe it:

Set up a free GitHub Action that runs every weekday at 9am, regenerates my "metrics strip" from content/achievements.md, and publishes the update automatically. Explain in plain English what it does, confirm it's free, and show me how to pause it.

When you hit a wall

You debug by asking. That's the whole skill.

You will get stuck — everyone does, and it's not a sign you're not technical enough. Being "technical" here just means being willing to describe the problem and ask. Claude is also your IT helpdesk: paste any error, screenshot, or "this looks wrong" straight into the chat. The four-move recovery loop:

📋

1 · Describe

"Here's exactly what I did, what I expected, and what happened instead."

🔍

2 · Ask to diagnose

"Explain what went wrong like I've never seen code, and propose 2 fixes."

🔧

3 · Fix one thing

"Try the safest fix first. Change one thing, then tell me how to check it."

↩️

4 · Verify or revert

"If that didn't work, undo it and take us back to the last version that worked."

🛟 COPY-PASTE RESCUE PROMPTS

Site didn't update?  "My live site still looks old after a few minutes — did you actually push to GitHub? Walk me through checking Settings → Pages." (Also: hard-refresh with Cmd/Ctrl+Shift+R.)

Page looks broken?  "The page looks broken — diagnose it, fix it, and if needed revert to the last good version. Nothing should be lost."

An error message you don't understand?  "I got this error: [paste it]. What does it mean in plain English, and what's the safest next step?"

Claude did something you didn't want?  "That's not what I meant — undo it. Here's what I actually want: [describe]. Add a rule to CLAUDE.md so this doesn't happen again."

✅ HOW TO VERIFY (since you can't read the code)

You don't check the work by reading code — you check it the way you'd check an analyst: by the result. (1) Look at the live page in your browser, on desktop and phone. (2) Click every link and button. (3) Read every number aloud against your real figures. (4) Ask Claude: "review the whole site as a skeptical recruiter and a CFO — flag weak headlines, vague claims, typos, and any number not backed by my content/ files." Seeing the result and trusting your judgment is the verification.
